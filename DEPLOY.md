# Деплой на VPS

Аквариум за Caddy: сервер отдаёт страницы по HTTP внутри докер-сети, наружу
торчит только прокси и он же держит HTTPS. Данные — в томе, пак моделей —
отдельной папкой, потому что в репозиторий он не входит.

## Что понадобится

- VPS: 1 ядро, 1 ГБ памяти, 20 ГБ диска. Этого хватает с запасом — сервер
  без зависимостей и почти не ест память, диск съедают только рисунки.
- Домен и **A-запись** на адрес VPS. Без домена Caddy не выпишет сертификат.
- Порты 80 и 443 открыты (Let's Encrypt проверяет домен по 80).

## Один раз

**1. Докер на сервере**

```bash
curl -fsSL https://get.docker.com | sh
```

**2. Код**

```bash
git clone <адрес репозитория> /opt/aqua
cd /opt/aqua
```

**3. Настройки**

```bash
cp .env.example .env
nano .env            # AQUA_DOMAIN и AQUA_EMAIL — обязательно
```

**4. Пак моделей**

В репозитории его нет. Собираешь у себя на Windows и копируешь на сервер:

```powershell
# у себя: FBX из купленного архива → glTF
powershell -ExecutionPolicy Bypass -File tools\convert-pack.ps1

# и на сервер (из папки проекта)
scp -r assets\models\pack root@СЕРВЕР:/opt/aqua/pack
```

Проверить, что доехало: `ls /opt/aqua/pack | wc -l` — должно быть 28 папок,
в каждой `.gltf`, `buffer.bin` и текстура.

**5. Папка данных**

Контейнер работает не под root, поэтому владельца надо проставить заранее:

```bash
mkdir -p /opt/aqua/data
chown -R 1000:1000 /opt/aqua/data
```

**6. Запуск**

```bash
docker compose up -d --build
docker compose logs -f aqua     # «Аквариумы: http://localhost:8000/»
```

Через полминуты `https://твой-домен` открывается с сертификатом.

## Каждый день

```bash
# посмотреть, что происходит
docker compose logs --tail 50 aqua

# обновить после правок
git pull && docker compose up -d --build

# остановить
docker compose down
```

Пересборка образа данные не трогает: аквариумы лежат в томе `./data`,
пак — в `./pack`, оба монтируются снаружи.

## Бэкап

Единственное, что нельзя потерять, — `data/`: там детские рисунки, имена
аквариумов и хеши паролей. Всё остальное восстанавливается из репозитория
и с твоего компьютера.

```bash
# /etc/cron.d/aqua-backup — раз в сутки, храним две недели
0 4 * * * root tar czf /var/backups/aqua-$(date +\%F).tgz -C /opt/aqua data && \
          find /var/backups -name 'aqua-*.tgz' -mtime +14 -delete
```

И хотя бы раз в месяц копию с сервера к себе — `scp` или `rsync`. Бэкап,
который лежит на том же диске, что и данные, бэкапом не является.

## Что важно знать про доступ

Аквариум устроен так, что **ссылка = право смотреть и добавлять рыбок**,
а пароль нужен только на необратимое (удалить рыбок или аквариум,
переименовать, сменить пароль). Это сделано ради ребёнка: он открывает
съёмку с телефона по ссылке, и пароля у него нет.

Отсюда следствия для публичного сервера:

- Кто угодно может завести аквариум на твоём сервере. Ограничено:
  `AQUA_TANKS_PER_HOUR` (5 с адреса в час) и `AQUA_MAX_TANKS` (200 всего).
- Кто угодно со ссылкой на аквариум может залить туда картинки. Ограничено:
  `AQUA_MAX_FISH` (40 на аквариум), `AQUA_MAX_BG` (8 своих фонов),
  размером картинки (3 МБ рыбка, 6 МБ фон) и общим `AQUA_MAX_DATA_MB`.
- Все пределы меняются в `.env` без правки кода.

Если хочется, чтобы аквариум был только для своих, самый простой способ —
basic-auth на прокси. В `Caddyfile`:

```
basic_auth {
	мама $2a$14$...   # хеш: docker run --rm caddy caddy hash-password
}
```

Только помни: тогда пароль спросят и у ребёнка на съёмке, и у телевизора.

## Если что-то не так

| Симптом | Куда смотреть |
|---|---|
| Сертификат не выписался | `docker compose logs caddy`; чаще всего A-запись не доехала или 80 порт закрыт |
| Аквариум пустой, рыбок нет | пак не скопирован: `ls /opt/aqua/pack`, `curl -s localhost/api/pack \| head -c 200` |
| «сервер недоступен» на странице | `docker compose ps`, `docker compose logs aqua` |
| Не сохраняются аквариумы | владелец `data/`: `ls -ln /opt/aqua/data` — должен быть 1000:1000 |
| Кончилось место | `du -sh /opt/aqua/data`, потом `AQUA_MAX_DATA_MB` или чистка `data/trash-tanks` |
